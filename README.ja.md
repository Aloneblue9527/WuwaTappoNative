# Wuwatappo Native

Wuwatappo Native は WuwaTappo 1.0.2 の Windows ネイティブ実装です。C# / .NET 8、WinForms、WebView2 で書かれており、Kuro Games 公式のデスクトップペットサービスに接続します。本プロジェクトは Kuro Games の公式プロジェクトではありません。

> アプリ内の英語/日本語 UI は現在プレビュー版のため、一部の表示が中国語のままになる場合があります。Windows インストーラーの UI は中国語のみです。

## 機能説明（要点）

**実装済み機能：**

- ✅ オリジナル版のすべてのオンラインコンテンツとマルチプレイに対応
- ✅ 中国サーバーと国際サーバー（Global）の切り替え、および公式ログインの引き継ぎに対応
- ✅ 国際サーバーのブラウザ認証ログインに対応（メール / X / Google は検証済み。その他の方式は未検証のため自己責任でテスト）
- ✅ 簡体字中国語 / English / 日本語の UI に対応（英語・日本語はプレビュー版で、一部の表示は中国語のまま）
- ✅ 中国サーバーの電話番号 + SMS 認証コードによるログイン（Kuro Games 通行証）に対応
- ✅ すべてのスキンのカスタマイズに対応（他人のルームでは実際に所持しているスキンのみが表示されますが、ローカルでは任意のスキンを設定できます）
- ✅ 任意のエモート送信に対応（所持状況を無視、キャラクターの制限を無視、他のプレイヤーにも表示されます）
- ✅ ヘッドアクセサリーの位置、自由な拡大縮小、回転の微調整に対応し、ヘッドアクセサリーごとに個別に保存
- ✅ カスタムコンパニオンに対応：ローカル装飾ペット、ランダム一括追加、複数選択削除、個別位置、一時非表示
- ✅ キャラクターとアクセサリーの外観ローテーションに対応し、間隔を設定して自動切り替え
- ✅ 宝箱通知をレアリティとカテゴリでフィルター可能
- ✅ トレイメニューから他のキャラクターのペットをすばやく非表示にできる
- ✅ テーマカラーから配色セット全体を自動生成、スムーズなカラーピッカー、画像からの自動色抽出に対応
- ✅ 操作パネルの背景画像アップロード、透明度/ぼかしの調整、テーマプリセットの保存と自動ローテーションに対応
- ✅ メインデスクトップペット/リモートキャラクターのフッターバー配色を個別に設定可能。キーボード、音ゲーモード、鳴潮、ゲームパッドは統一して追従
- ✅ メインデスクトップペットとリモートキャラクターのフッターバーをそれぞれ非表示にでき、単一キーまたは 2 キーのショートカットキーで切り替え可能
- ✅ パネルの最大化、8 方向からのエッジリサイズに対応し、パネルのサイズと最大化状態を記憶
- ✅ F8 によるマルチモニター切り替えに対応：デフォルト位置のメンバー、主人公のみ、全メンバーの 3 種類の戦略で、解像度をまたいで比例マッピング
- ✅ マルチプレイのデスクトップペットとカスタムコンパニオンで Ctrl による複数選択、Ctrl+A による全選択、グループ全体のドラッグによる端への吸着、空白クリックによる選択解除に対応
- ✅ 設定ページでサーバーが現在配信しているすべてのお知らせを確認可能（既読状態を含む）
- ✅ Key 数の調整（ワンクリックで +10000）に対応し、1000 未満のときに自動で補完
- ✅ 自動昇階合成とワンクリックでの一括昇階に対応
- ✅ 正式版 / テスト版の更新チャンネルに対応
- ✅ 宝箱の自動受け取りに対応
- ✅ 自動エモート、自動クリック、ゲームモードのルールに対応
- ✅ ホットキーと設定項目の検索に対応
- ✅ コントローラープロトコル拡張で、XInput コントローラー未検出時に PS / Switch などの DirectInput コントローラーに対応し、有線 DualSense のスティックとアナログトリガーにも対応（単一コントローラー）
- ✅ 現在のキーボード/ゲームパッドのキー配置を表示し、テーマ配色に追従
- ✅ 音ゲーモードは 4K / 5K / 6K に対応し、モードごとにキー配置を個別に保存。スペースや ; ' , . / などの記号キーも設定可能
- ✅ ワンクリックで公式のログイン状態を引き継ぎ
- ✅ 配信者モードの OBS キャプチャウィンドウに対応（背景色のカスタマイズ/透明背景）
- ✅ マルチプレイキャラクターとカスタムコンパニオンの自動回避、仮想グリッドへの吸着（メインキャラクターを除く。左右の基準位置を選択でき、既定は右）、横方向/縦方向の整列、並び順のリセットに対応
- ✅ マルチプレイメンバーの個別の表示/非表示に対応し、メンバーごとに設定を保存
- その他、さまざまな最適化機能があります……

**細かな最適化：**

- メモリ最適化：同じシナリオ（12 人同時表示）で、公式版の実行メモリが 650MB であるのに対し、本バージョンは 80MB
- マルチプレイでは全員の位置を保存。相手が切断して再入室した場合でも、ソフトウェアを再起動した場合でも、全員が元の位置を維持
- 配信キャプチャの最適化：独立したキャプチャ可能なウィンドウを使用し、ウィンドウ解像度をカスタマイズ可能。低画質を回避

## インストール

### リリースパッケージを使用する

[GitHub Releases](https://github.com/DanielToyama/WuwaTappoNative/releases) からダウンロードします：

> インストーラーの UI は現在中国語のみです。以下に引用している選択肢名は、実際のインストーラー表示どおり中国語で記載しています。

- `WuwatappoNative-<version>-Setup.exe`：`%LOCALAPPDATA%\Programs\Wuwatappo Native` にインストールします。既定では管理者マニフェストが含まれており、起動時にインストールモードが表示され、既定で「为所有用户安装（推荐）」が選択されます。これを選択すると UAC が要求され、管理者モードのデスクトップペットを終了できるようになります。現在のユーザーのみを対象とした標準権限でのインストールも選択できます。
- `WuwatappoNative-<version>-portable.zip`：解凍後、`WuwatappoNative.exe` を直接実行します。

### テスト版（Beta）

`main` へのプッシュで、テストパッケージに含まれるソース、アセット、ビルドスクリプトに変更があるたびに GitHub Actions の `Beta build` がトリガーされ、テストバージョン番号付きのテスト版が自動生成されて GitHub Releases の Pre-release として公開されます。ドキュメント、workflow、テストコードなどの変更のみではテストパッケージは再生成されません。

- テスト版のバージョン番号形式：`<next patch version>-beta.<run_number>`（例：`0.3.3-beta.123`）。
- テスト版 Release のタイトルと説明には、今回のビルドの送信日時（UTC+8）が付記されるため、同じローリング Release の複数回の更新を判別しやすくなります。
- ダウンロード方法 1：[GitHub Releases](https://github.com/DanielToyama/WuwaTappoNative/releases) を開き、**Pre-release** とマークされた `v<next patch version>-beta`（例：`v0.3.3-beta`）を探し、対応するテストバージョン番号の `WuwatappoNative-<beta version>-Setup.exe` または `WuwatappoNative-<beta version>-portable.zip` をダウンロードします。
- ダウンロード方法 2：[Beta build Actions](https://github.com/DanielToyama/WuwaTappoNative/actions/workflows/beta.yml) の直近の実行を開き、ページ下部の **Artifacts** から `WuwatappoNative-beta-<run_number>` をダウンロードします。圧縮パッケージには Setup とポータブル版が含まれています。
- テスト版はインストーラーとポータブル版の両方を提供します。インストーラーは正式版と同様に「为所有用户安装」または「仅当前用户安装」を選択でき、ポータブル版は解凍後に `WuwatappoNative.exe` を実行します。テスト版は自動更新を提供せず、安定性と互換性も保証しません。
- 正式版リリースのコミットでは新しいテストパッケージのビルドがトリガーされなくなり、正式リリース時にテスト版が混入するのを防ぎます。
- テスト版と正式版はどちらも `設定 → 更新 → 更新チャンネル` で正式版またはテスト版を選択できます：正式チャンネルは正式版のみを受信し、テストチャンネルは正式版と以降のテスト版の両方を受信します。更新が見つかっても手動でダウンロード・インストールする必要があり、サイレントアップグレードは行われません。
- テスト版と正式版は `%LOCALAPPDATA%\WuwatappoNative` 設定ディレクトリを共用します。テスト前に実行中の旧インスタンスを終了することをおすすめします。設定が変更されるのが心配な場合は、事前にこのディレクトリをバックアップしてください。
- フィードバックの際は、テストバージョン番号、再現手順、関連ログを添えて [GitHub Issues](https://github.com/DanielToyama/WuwaTappoNative/issues) に投稿してください。**token、アカウント認証情報、認証情報を含むスクリーンショットはアップロードしないでください。**
- 日常的に使用する場合は、Releases の Pre-release ではない正式版をダウンロードしてください。テスト版は正式版の更新チェックに影響しません。

システム要件：

- Windows 10/11 x64。
- WebView2 Runtime。Windows 10/11 には通常プリインストールされています。存在しない場合、パネルは表示できませんが、デスクトップペット自体は動作します。
- リリースパッケージを使用する場合、.NET Runtime のインストールは不要です。

新しいバージョンをインストールまたは起動する前に、トレイから実行中の旧インスタンスを終了してください。

## クイックスタート

1. プログラムを起動します。初回起動時はメインパネルが開き、免責事項が表示されます。確認すると、プログラムはその状態を記憶します。
2. パネルでログインします：
   - **UID + 認証コード**：9〜10 桁のゲーム UID を入力し、6 桁の認証コードを取得して入力します。
   - **電話番号 + SMS 認証コード**：中国サーバーではログインページで「電話番号ログイン」に切り替え、Kuro Games 通行証の電話番号でログインできます。
   - **国際サーバーのブラウザ認証ログイン**：国際サーバーを選択後、ログインページの案内に従ってブラウザでメール / X / Google の認証を完了します。その他のログイン方式は未検証のため、自己責任でテストしてください。
   - **公式プログラムのログイン状態を引き継ぐ**：`設定 → アカウント → 公式クライアントのログイン状態を引き継ぐ` を開くと、プログラムは本機の公式 WuwaTappo のログインデータを読み取り、実行中の公式クライアントを終了します。
   - **token をインポート**：`token-extractor/` 内の独立したツールで `kuro_infoToken` を読み取り、設定に貼り付けてインポートできます。
3. `設定 → アカウント → サーバーリージョン` で中国サーバー（CN）または国際サーバー（Global）を選択します。サーバーを切り替えると現在のアカウントからログアウトし、再ログインが必要になります。
4. `マルチ` を開き、ルームを作成するかルーム番号を入力して参加します。参加に成功すると、ルームのメンバーが右側のメンバー一覧に表示されます。新しいメンバーがルームに戻ってきたときは、保存された位置の復元が優先されます。既存メンバーとの重なりが可視面積の 30% を超える場合は、現在の横方向/縦方向の並び順に従って再配置されます。位置が保存されていないメンバーも、並び順の方式に従って位置が作成されます。
- ホストのルームは `rm` スナップショットから自動的に識別され、永続化されます。自動復帰はサーバーの `user/me.room_no` のみを基準とし、ローカル記録がサーバー状態を上書きすることはありません。ホストのルームへ自動復帰するときはルーム socket に直接接続し、`rooms/join` は呼び出しません。手動で退出する場合やホストのルームを切り替える場合は、事前に二次確認のダイアログが表示されます。
5. 初回実行時に以下のファイルが作成されます：

```text
%LOCALAPPDATA%\WuwatappoNative\config.json
%LOCALAPPDATA%\WuwatappoNative\state.json
%LOCALAPPDATA%\WuwatappoNative\click_ledger.json
%LOCALAPPDATA%\WuwatappoNative\logs\app-YYYY-MM-DD.log
%LOCALAPPDATA%\WuwatappoNative\logs\synth-YYYY-MM-DD.jsonl
%LOCALAPPDATA%\WuwatappoNative\logs\diag-YYYY-MM-DD.log
%LOCALAPPDATA%\WuwatappoNative\cache\
```

`config.json` はログイン状態、外観、設定を保存します。`state.json` はウィンドウ位置、ルーム状態、メンバーの位置、メンバーの表示状態を保存します。`click_ledger.json` はアカウント/サーバーごとに累計クリック数と未報告のクリック数を保存します。`cache\` は外観と画像のキャッシュを保存します。

ログディレクトリの説明：

- `logs\app-YYYY-MM-DD.log`：通常の実行ログ。起動時にバージョン/システム/画面 DPI/主要設定を記録します。`--verbose` 指定時は追加で `DBG` デバッグ行を出力します。1 ファイルが 16MB を超えると `app-YYYY-MM-DD.1.log` の分割ファイルが生成されます。
- `logs\synth-YYYY-MM-DD.jsonl`：合成スナップショット。1 行につき 1 つの JSON 操作です。実際に自動/手動合成を開始するたびに、操作 id、設定、初期バッグ素材、各ラウンドの消費と応答、結果、所要時間を記録します。自動の空チェック（合成を開始しなかった場合）は書き込みません。1 ファイルが 32MB を超えると分割されます。
- `logs\diag-YYYY-MM-DD.log`：診断ログ。z-order/Issue #13 の現場スナップショット（トップレベルウィンドウの順序、デスクトップペットの topmost/cloaked、`WindowFromPoint` のヒット、上部の外部ウィンドウ）、WebView2 の故障などを含みます。1 ファイルが 16MB を超えると分割されます。
- 3 種類のログはいずれも直近 7 自然日（当日を含む）分のみ保持し、最終書き込み時刻に基づいて自動的にクリーンアップされます。旧バージョンのルートディレクトリの `log.txt` は起動時に対応する日付の app ログへ移行され、7 日を超えている場合はそのまま削除されます。
- すべてのログに token、Cookie、Authorization などの認証情報は記録されません。

## 使い方と設定

### パネルとデスクトップペット

パネルには `バッグ`、`図鑑`、`合成`、`プリセット`、`マルチ`、`設定` の 6 つのページがあります。

デスクトップペットの操作：

- デスクトップペットをドラッグすると位置を移動できます。画面またはタスクバーの端から約 28 ピクセル以内にドラッグすると自動的に吸着します。
- デスクトップペットを右クリックするとメニューが開き、パネルを開く、エモートホイール、常に最前面、ホバー時に半透明、マウス透過、ペットサイズ、ペットの不透明度、位置をリセット、ペットを再起動、終了が含まれます。
- マルチプレイキャラクターを右クリックすると、「リモートペットのサイズ」と「リモートペットの不透明度」を個別に調整できます。この 2 項目はすべてのマルチプレイキャラクターに一律に適用され、主人公には影響しません。
- `設定 → ペットとウィンドウ` では、ペットサイズ 25%–200%、ペットの不透明度、リモートペットのサイズと不透明度（いずれも既定ではメインに追従し、個別にカスタマイズも可能）、リモートプレイヤー名のサイズ（50%–200%）、アニメーション FPS（30 / 60 / 120、既定 60）、マウス透過、ホバー時に半透明、ホバー時の透明度（10%–100%、既定 40%）、および OBS キャプチャウィンドウのサイズ、背景色/透明背景、互換モード、「デスクトップのメインを描画しない」を調整できます。
- マルチプレイページのマルチプレイキャラクターのスタイルと宝箱開封ボタンは、設定に統合されました。
- マウス透過を有効にすると、デスクトップペットはマウスクリックを受け付けません。右クリックメニューまたは `F7` で復元できます。
- OBS キャプチャウィンドウのウィンドウタイトルは `Wuwatappo Capture` で、OBS のウィンドウキャプチャで使用できます。背景は任意の色番号に設定するか透明にできます（透明モードでは、OBS のウィンドウキャプチャで「透明度を許可」（中国語 UI では「允许透明」）にチェックを入れる必要があります）。初回有効時には、キャプチャ方法を Windows 10（1903 以上）に変更するよう案内が表示されます。OBS でまだ黒い影が表示される場合は、互換モードを有効にして通常のウィンドウレンダリングにフォールバックできます。
- 「ペットを再起動」は現在のプロセスを終了して再起動し、単一インスタンスロックは自動的に引き継がれます。

### デフォルトのホットキー

| 機能 | デフォルトキー |
|---|---|
| ゲームモード（マウス透過）の切り替え | `F7` |
| 画面の切り替え | `F8` |
| デスクトップペットの表示/非表示 | `F9` |
| 画面の更新 | `F5` |
| エモートスロット 1–6 の送信 | `Ctrl+Alt+1` 〜 `Ctrl+Alt+6` |

`OBS キャプチャウィンドウ`、`メインパネルを開く`、`音ゲーモード切り替え`、`自動エモート切り替え`、`自動クリック切り替え` などの機能は既定ではキーを占有せず、設定ページで必要に応じてバインドできます。`メインパネルを開く` は `バッグ` のホームに戻り、前回表示していたページは保持されません。

ホットキーは `設定 → デスクトップキーボード → ホットキー` で記録、クリア、既定値への復元ができます。保存後すぐに反映されます。ホットキーは Raw Input によるパッシブな監視で、システムレベルのホットキーを登録しないため、他のソフトウェアと競合しません（競合した場合は両方ともトリガーされます）。

### 設定

| 設定場所 | 内容 |
|---|---|
| `設定 → アカウント` | サーバーリージョン、ログイン、公式ログインの引き継ぎ、token のインポート、ログアウト、アカウント情報の更新、累計クリックの補充 |

エモートの取得元は、クイックバーからランダム、指定エモート、全エモートからランダムのいずれかを選択でき、送信頻度の上限は 1〜20 回/秒です。自動クリックの頻度は 1〜10 回/秒で、仮想タップ動作を表示するかどうかは個別に設定できます。

`設定 → その他 → ゲームモードのルール` にはプロセス名を入力できます（例：`WutheringWaves.exe`）。ルールに一致するとプログラムは自動的にマウス透過を有効にし、プロセス終了後に元に戻ります。名前の照合は大文字小文字を区別せず、`.exe` の有無も問いません。

### 自動起動と管理者権限

- `設定 → その他 → スタートアップに登録` は現在のユーザーの自動起動を制御します。
- 通常権限では `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` を使用します。
- 管理者権限では、現在のユーザーのログオンでトリガーされる最高権限のスケジュールタスクを使用し、ログオン時に UAC は表示されません。
- `設定 → その他 → 管理者として起動` は、管理者権限で実行されているフォアグラウンドプログラムの Raw Input を受信するために使用します。手動で起動する際は UAC が要求されます。

### 更新

設定ページ下部の「更新を確認」は GitHub Releases を読み取ります。現在のバージョンが複数バージョン遅れている場合、更新説明にはそれらのバージョンの更新内容が新しい順に一覧表示され、設定ページの更新バナー内でスクロール表示されます。更新説明は中国語 / English / 日本語に対応し、現在の表示言語の内容だけが表示されます。プログラムは更新を自動インストールしないため、Release ページから新しい Setup またはポータブル版をダウンロードする必要があります。

バージョン互換性ステータスページ：<https://code.danieluu.top/WuwaTappoNative/>。ページとクライアントの両方が同じ `docs/compatibility.json` を読み取り、現在のバージョンが安全な互換範囲内にあるかどうかを表示します。

## パフォーマンス

44 名のメンバーが毎秒 10 回全員分のキー入力を行う負荷テストで、シングルコアの約 6.7% を占有し、アクションの滞留はありません。キャラクターをドラッグしている間、キーボードは移動のみで再描画されません。負荷テストコマンド：

```powershell
WuwatappoNative.exe --stress 44 --stress-hz 10
```

吹き出しアニメーションは、アクティブ時のみ有効になる UI アニメーションクロックを使用し、キー入力、カウント、アニメーションの再描画を統合し、現在のキャラクター、フッターバー、吹き出しのサムネイルをキャッシュします。システム全体のタイマー精度は変更しません。アニメーションフレームレートは設定で 30 / 60 / 120 から選択でき（実際は約 30 / 61 / 120 回/秒）、切り替え後すぐに反映されます。フレームレートが高いほど、デスクトップペットウィンドウの再描画とサブミットの頻度が上がります。オフラインで実行できるアニメーション回帰チェックと描画ベンチマークを実行できます：

```powershell
dotnet run --project tests/AnimationChecks/AnimationChecks.csproj -c Release
```

このチェックはメインアプリケーションを起動せず、デスクトップペットを表示せず、アカウント設定も読み取りません。クロック周波数とオフスクリーン描画時間は実際の表示 FPS とは等しくなく、ゲームの最前面表示、レイトレーシング、フレーム生成の互換性に関する結論を示すものでもありません。

## 制限事項

- 電話番号ログインは中国サーバーのみ対応しています。国際サーバーでは、ブラウザ認証ログイン（メール / X / Google は検証済み。その他の方式は自己責任でテスト）、公式クライアントのログイン引き継ぎ、または token のインポートを使用してください。
- 国際サーバーの通行証アカウントは、ゲームキャラクターを連携していなくてもアカウントレベルの token を取得してログインできます。キャラクター/プレイヤー情報に依存する一部の機能は使用できない場合があります。
- 公式クライアントが App-Bound Encryption（v20）を使用している場合、その cookie を復号できないため、UID 認証コード、電話番号ログイン、または国際サーバーのブラウザ認証ログインに切り替える必要があります。
- 通常権限のプロセスは、管理者権限のフォアグラウンドウィンドウの Raw Input を受信できません。このシナリオが必要な場合は、管理者権限での起動を有効にしてください。
- マルチプレイ、宝箱の開封、アカウント情報は Kuro Games のサーバーに依存します。ネットワークに到達できない場合やサーバーが利用できない場合、関連する機能は使用できません。
- Windows 10/11 x64 のみ対応しています。
- 本プロジェクトは Kuro Games の公式プロジェクトではありません。ゲーム素材の著作権は Kuro Games に帰属します。詳細は [NOTICE.md](NOTICE.md) と [assets/README.md](assets/README.md) を参照してください。


### ソースからのビルド

要件：

- Windows 10/11 x64
- Git
- .NET 8 SDK

```powershell
git clone https://github.com/DanielToyama/WuwaTappoNative.git
cd WuwaTappoNative
dotnet build -c Release
.\bin\Release\net8.0-windows\WuwatappoNative.exe
```

リポジトリにはビルドと実行に必要なデフォルト素材とオフライン外観ディレクトリが含まれているため、追加の素材パックをダウンロードする必要はありません。

メインプログラムと独立したログイン抽出ツールは、いずれも `SQLitePCLRaw.bundle_e_sqlite3` 2.1.14 に固定されており、実際にはネイティブ SQLite 3.54.0 を読み込み、[CVE-2025-6965](https://github.com/advisories/GHSA-2m69-gcr7-jv3q) は修正済みです。必要に応じて依存関係グラフと読み取り互換性を再確認できます：

```powershell
dotnet list WuwatappoNative.csproj package --vulnerable --include-transitive
dotnet list token-extractor/WuwatappoTokenExtractor.csproj package --vulnerable --include-transitive
dotnet run --project tests/SqliteChecks/SqliteChecks.csproj -c Release
```

チェックスクリプトはインメモリデータベースのみを使用し、本機の実際の cookies やアカウントデータは一切読み取りません。
